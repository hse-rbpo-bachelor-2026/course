# Вклад участников

**Файл:** обязательный `CONTRIBUTIONS.md`; форма ниже рекомендуется. Файл впервые создаётся на [S04](../seminars/S04/README.md), дорабатывается к EK1 и поддерживается далее. Добавьте ссылку из входной страницы проекта.

**Назначение:** быстро показать конкретный результат каждого участника и проверяемый след. Это навигатор по вкладу, а не дневник действий или журнал часов.

## Форма для копирования

Скопируйте блок в `CONTRIBUTIONS.md`, замените подсказки результатами своего проекта. Для команды из двух удалите M3. Добавляйте строки по содержанию работы.

```markdown
# Вклад участников

## M1

| Результат | Вклад | Проверяемый след |
| --- | --- | --- |
| SR / T / D / код / другой полученный результат | Что конкретно сделал участник | Прямая ссылка на раздел, файл, commit или PR |

## M2

| Результат | Вклад | Проверяемый след |
| --- | --- | --- |
| ... | ... | ... |

## M3

| Результат | Вклад | Проверяемый след |
| --- | --- | --- |
| ... | ... | ... |
```

## Пояснения — не копировать в проект

**Компактность.** К EK1 ориентир — 2–3 конкретных результата участника, не квота. Крупный наблюдаемый результат не нужно дробить. Включайте и ранее выполненную работу собственного проекта; учебные заметки Lab Booking её не заменяют. Достаточно кратких записей по полученным результатам и актуализации к контрольным точкам; отдельная еженедельная отчётность не требуется.

**Конкретный вклад.** Вместо «работал над требованиями» укажите, например: «SR-03 — сформулирован критерий приёмки ограничения доступа». Ссылка должна вести к самому результату или его изменению. Отдельный commit для каждой строки и искусственная история не нужны.

**Совместная работа.** Один результат может быть у нескольких участников с различимыми пояснениями: M1 сформулировал требование, M2 проверил его на отрицательном случае и уточнил критерий. Одинаковую запись всем копировать не следует. Постоянные учебные роли и проценты участия не требуются.

**Обозначения.** Используйте постоянные `M1–M3`; ФИО, группы, личные email и соответствие GitHub-аккаунтам передаются через закрытую регистрацию. Коды не означают должности или старшинство.

**Фактические результаты.** Записывайте уже полученный результат, а не запланированную работу. Тесты и автоматизированные проверки добавляются после выполнения; на S04 они ещё не обязательны. Будущая проверка D не равна выполненному тесту. `AI_USAGE.md` отдельно показывает существенное применение ИИ и человеческую проверку; подробности — в [политике ИИ](../ai-usage.md).

**Повышенный уровень.** Для 9–10 укажите личный вклад в контрпример, уточнение цепочки или сравнение альтернатив обычной строкой со ссылкой. Отдельная карта не нужна; участник самостоятельно объясняет анализ по [правилам оценивания](../grading.md).

После EK1 добавляйте новые результаты по мере их появления. Старые содержательные записи сохраняйте; мелкие связанные записи можно укрупнять.
