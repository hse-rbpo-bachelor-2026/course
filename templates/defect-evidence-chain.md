# Цепочка исправления или подтверждения свойства безопасности

Рекомендуемая форма для S06 и последующего переноса в проект. Обязателен проверяемый смысл связей; отдельный файл на каждую цепочку не требуется. Используйте существующее место хранения и ссылки на первичные материалы. Общие правила — в [evidence.md](../evidence.md).

## Форма для копирования: найден реальный дефект

```markdown
### Проверяемое утверждение
[Что было нарушено и что должно выполняться. Для своего проекта — связь с релевантными SR/T/D. Для учебного объекта достаточно контекста жалобы.]

### Исходный сценарий и наблюдение
- Объект и исходная версия: [...]
- Условия: пользователь, данные, настройки [...]
- Запрос или шаги: [...]
- Фактический результат до изменения: [...; ссылка на вывод]

### Причина и изменение
- Причина: механизм и место в коде [...]
- Исправляющее изменение: [...; ссылка на commit/diff]
- Проверенная исправленная версия: [...]

### Проверки и результаты
- Негативная: сценарий, ожидаемый результат, фактический результат до/после [...]
- Регрессионная: штатный сценарий и фактический результат [...]
- Команда/условия выполнения и ссылка на результаты: [...]

### Вывод и границы
[Что подтверждено этими проверками; что осталось вне области проверки.]
```

Повторная проверка подтверждает результат изменения. Если негативный и регрессионный тесты выполнены на исправленной версии, отдельный идентичный запуск не нужен.

## Форма для копирования: свойство уже обеспечено

```markdown
### Свойство и механизм
- Требуемое свойство: [...; для проекта — релевантные SR/T/D]
- Обеспечивающий механизм: [...; ссылка на реализацию]
- Версия и условия: [...]

### Проверки и результаты
- Позитивная: разрешенный штатный сценарий, ожидаемый и фактический результат [...]
- Негативная: недопустимый сценарий, ожидаемый и фактический результат [...]
- Команда/условия выполнения и ссылка на результаты: [...]

### Вывод и границы
[Что подтверждено и при каких ограничениях.]
```

Предварительная уязвимость для второй формы не требуется. Наличие фреймворка само по себе не заменяет проверку его фактического применения.

## Версия и первичные материалы

Commit/tag обозначает сохраненную версию. Если изменения в рабочей копии, укажите исходный commit и приложите diff; явно обозначьте это состояние. История Git подтверждает происхождение изменения, а фактический вывод тестов — проверенное поведение. Для общей работы различайте вклад участников в `CONTRIBUTIONS.md`.
