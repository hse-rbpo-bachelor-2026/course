# Требования безопасности

**Когда:** несколько рабочих SR с предварительными критериями — на [S02](../seminars/S02/README.md) (ориентир 2–3, не квота); связный набор с охватом значимых свойств — к S03. Имя файла выберите сами и добавьте ссылку из `PROJECT.md` или README проекта.

**Обязательно на S02:** устойчивый `SR-*`, проверяемое защитное свойство и критерий приёмки. Связи с `T-*` и `D-*` добавляются после введения соответствующих методов. Форма рекомендуется; ориентир 6–10 требований к EK1 не является квотой.

## Форма для копирования

Скопируйте содержимое блока в свой файл. Замените подсказки требованиями собственного проекта; строки учебного кейса переносить не нужно.

```markdown
# Требования безопасности

| ID | Требование | Критерий приёмки | Связанные T / D (позднее) |
| --- | --- | --- | --- |
| SR-01 | Какое защитное свойство обязательно и при каких условиях | Ситуация и ожидаемый наблюдаемый результат | — |
```

Добавляйте строки по содержанию. Вместо таблицы допустимы отдельные блоки с теми же сведениями.

## Пояснения — не копировать в проект

**Связь с безопасностью.** Для `SR-*` нужно обосновать защитное свойство и последствия нарушения — в формулировке, кратком контексте или по ссылке на описание продукта. Обычное проверяемое бизнес-правило без защитного смысла остаётся в предметном описании; отдельный реестр таких правил не нужен.

**Свойство и критерий.** Требование говорит, что продукт обязан обеспечить; критерий приёмки задаёт ситуацию и наблюдаемый результат. Общие фразы «защитить доступ» и названия технологий вроде JWT этого не заменяют. Разобранный пример — в [кейсе S02](../seminars/S02/requirements-case.md). Готовый тест на S02 не требуется; наличие критерия не означает выполнение требования.

**Связи.** На S02 в последней колонке ставьте `—`. На S03 появляются связи с `T-*`, на S04 — с `D-*`. Обратные ссылки в каждой строке не обязательны, если цепочка однозначно прослеживается в других артефактах. Отдельная матрица не нужна.

**Краткая самопроверка:** требование относится к продукту, выражает защитное свойство, не дублирует другую запись и имеет наблюдаемый критерий. Выбранная технология сама по себе требованием не является.

При уточнении формулировки или критерия сохраняйте ID, пока смысл свойства прежний. Нумерация не задаёт приоритет; освободившийся ID не используйте для другого свойства.
